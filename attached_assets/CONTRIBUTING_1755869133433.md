## 📜 Código de Conducta

### Nuestro Compromiso

Nos comprometemos a hacer de la participación en nuestro proyecto una experiencia libre de acoso para todos, independientemente de:
- Edad, tamaño corporal, discapacidad visible o invisible
- Etnia, características sexuales, identidad y expresión de género
- Nivel de experiencia, educación, estatus socioeconómico
- Nacionalidad, apariencia personal, raza, religión
- Identidad y orientación sexual

### Comportamientos Esperados

- Usar lenguaje acogedor e inclusivo
- Respetar diferentes puntos de vista y experiencias
- Aceptar críticas constructivas con gracia
- Enfocarse en lo que es mejor para la comunidad
- Mostrar empatía hacia otros miembros de la comunidad

### Comportamientos Inaceptables

- Uso de lenguaje o imágenes sexualizadas
- Comentarios despectivos, insultos o ataques personales/políticos
- Acoso público o privado
- Publicar información privada de terceros sin permiso
- Otras conductas que podrían considerarse inapropiadas en un entorno profesional

## 🤝 Cómo Contribuir

### Formas de Contribuir

1. **Reportar bugs** - Encuentra y reporta problemas
2. **Sugerir mejoras** - Ideas para nuevas funcionalidades
3. **Escribir código** - Implementar correcciones o nuevas características
4. **Mejorar documentación** - Clarificar y expandir la documentación
5. **Traducir** - Ayudar con traducciones a otros idiomas
6. **Probar** - Usar el sistema y reportar experiencias

### Primeros Pasos

1. **Fork** el repositorio
2. **Clonar** tu fork localmente
3. **Crear una rama** para tu contribución
4. **Hacer cambios** siguiendo los estándares
5. **Probar** tus cambios
6. **Crear Pull Request**

## 🐛 Reportar Bugs

### Antes de Reportar

- **Busca** en issues existentes para evitar duplicados
- **Actualiza** a la última versión para verificar si persiste
- **Reproduce** el bug de manera consistente

### Información a Incluir

```markdown
**Descripción del Bug**
Descripción clara y concisa del problema.

**Pasos para Reproducir**
1. Ir a '...'
2. Hacer click en '....'
3. Desplazarse hacia '....'
4. Ver error

**Comportamiento Esperado**
Descripción clara de lo que esperabas que pasara.

**Capturas de Pantalla**
Si aplica, agregar capturas para explicar el problema.

**Información del Sistema:**
- OS: [ej. Windows 10, Ubuntu 20.04, macOS 11.0]
- Navegador: [ej. Chrome 91, Firefox 89, Safari 14]
- Versión de Node.js: [ej. 16.14.0]
- Versión de SISAE: [ej. 1.0.0]

**Logs**
Copiar logs relevantes del servidor o consola del navegador.
```

## 💡 Sugerir Mejoras

### Antes de Sugerir

- **Revisa** la documentación para entender las capacidades actuales
- **Busca** en issues para ver si ya fue sugerido
- **Considera** si la mejora beneficia a la mayoría de usuarios

### Formato de Sugerencia

```markdown
**¿Tu solicitud está relacionada a un problema?**
Descripción clara del problema. Ej: "Estoy frustrado cuando [...]"

**Solución Propuesta**
Descripción clara de lo que quieres que ocurra.

**Alternativas Consideradas**
Descripción de soluciones alternativas que consideraste.

**Contexto Adicional**
Cualquier otra información, capturas o mockups sobre la solicitud.
```

## 💻 Desarrollo Local

### Prerrequisitos

```bash
# Node.js 16 o superior
node --version

# NPM 8 o superior
npm --version

# Git
git --version
```

### Configuración del Entorno

```bash
# 1. Fork y clonar el repositorio
git clone https://github.com/tu-usuario/sisae.git
cd sisae

# 2. Instalar dependencias
npm install

# 3. Crear rama para tu feature
git checkout -b feature/nueva-funcionalidad

# 4. Iniciar servidor de desarrollo
npm run dev
```

### Estructura del Proyecto

```
sisae/
├── 📁 client/              # Frontend
│   ├── index.html         # Página principal
│   ├── script.js          # Lógica del cliente
│   └── style.css          # Estilos
├── 📁 server/             # Backend
│   ├── server.js          # Servidor Express
│   └── routes/            # Rutas de la API
├── 📁 data/               # Base de datos
│   └── sanciones.json     # Datos locales
├── 📁 tests/              # Pruebas
├── 📁 docs/               # Documentación
└── 📁 scripts/            # Scripts de utilidad
```

### URLs de Desarrollo

- **Frontend:** http://localhost:80
- **API:** http://localhost:80/api
- **Documentación:** http://localhost:80/docs

## 🔄 Proceso de Pull Request

### Antes de Crear el PR

1. **Sincronizar** con la rama principal
```bash
git checkout main
git pull upstream main
git checkout tu-rama
git rebase main
```

2. **Probar** todos los cambios
```bash
npm test
npm run lint
npm start  # Verificar que funciona
```

3. **Documentar** cambios significativos

### Creando el Pull Request

1. **Título descriptivo:** `feat: agregar filtro avanzado por deportes`

2. **Descripción completa:**
```markdown
## 📝 Descripción
Implementa filtro avanzado que permite seleccionar múltiples deportes simultáneamente.

## 🎯 Tipo de Cambio
- [ ] Bug fix (corrección que soluciona un problema)
- [x] Nueva funcionalidad (cambio que agrega funcionalidad)
- [ ] Breaking change (correción o funcionalidad que causa que funcionalidad existente no funcione como se esperaba)
- [ ] Este cambio require actualización de documentación

## 🧪 Pruebas
- [x] Probado en Chrome, Firefox, Safari
- [x] Probado en Windows y macOS
- [x] Verificado funcionamiento offline
- [x] Probado con datos de ejemplo

## 📷 Capturas de Pantalla
(si aplica)

## 📋 Checklist
- [x] Mi código sigue el estilo del proyecto
- [x] He realizado una auto-revisión de mi código
- [x] He comentado mi código, particularmente en áreas difíciles de entender
- [x] He realizado los cambios correspondientes a la documentación
- [x] Mis cambios no generan nuevas advertencias
- [x] He agregado pruebas que demuestran que mi corrección es efectiva o que mi funcionalidad funciona
- [x] Las pruebas unitarias nuevas y existentes pasan localmente con mis cambios
```

### Revisión del Código

- **Paciencia** - Las revisiones pueden tomar tiempo
- **Receptividad** - Acepta feedback constructivo
- **Colaboración** - Discute cambios sugeridos
- **Mejora continua** - Usa feedback para mejorar

## 🏷️ Etiquetas de Issues

- `bug` - Algo no funciona correctamente
- `enhancement` - Nueva funcionalidad o mejora
- `documentation` - Mejoras en documentación
- `good first issue` - Ideal para nuevos contributores
- `help wanted` - Se necesita ayuda de la comunidad
- `question` - Pregunta sobre el proyecto
- `priority: high` - Prioridad alta
- `priority: low` - Prioridad baja
